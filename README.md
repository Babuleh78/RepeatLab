# RepeatLab

Java CLI сохраняет исходные ячейки XLSX и формирует воспроизводимый аудит.
Python-пакет агрегирует уже классифицированные строки в заказы и строит историю
и целевую метку по этим заказам. Java clean преобразует проверенный raw-набор
в классифицированные события с полным учётом карантина. Обучение моделей пока не реализовано.

## Установка и проверки

Требуются Git, Eclipse Temurin **25.0.5+8**, uv **0.13.5** и Python **3.12.14**.
Укажите `JAVA_HOME` на каталог JDK и добавьте его `bin` в `PATH`.
Maven Wrapper скачивает Maven **3.10.0** с проверкой SHA-256; системная установка
Maven не нужна. В Windows используйте `./mvnw.cmd`, в Linux/macOS — `sh ./mvnw`.

```text
uv python install
sh ./mvnw -B -f java/pom.xml verify
uv sync --locked --dev
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy src tests
uv run --locked pytest
uv build --no-sources
```

На Windows весь набор проверок запускается командой `./scripts/check.ps1`.
Если uv установлен через WinGet, скрипт найдёт его и при отсутствии команды в PATH.
Установка закреплённой версии:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/0.13.5/install.ps1 | iex"
```

После установки откройте новый терминал и проверьте `uv --version`.
[Инструкция установки uv](https://docs.astral.sh/uv/getting-started/installation/).

## Загрузка и аудит XLSX

```text
java -jar java/target/repeatlab-data.jar --help
java -jar java/target/repeatlab-data.jar ingest --input data/raw/source.xlsx --output data/processed/run-001
```

Родительский каталог output должен существовать, сам output должен быть новым.
CLI не скачивает исходники. Встроенный профиль `online-retail-v1` соответствует
колонкам [Online Retail II, Daqing Chen (2012)](https://doi.org/10.24432/C5CG6D),
лицензия [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
[Страница источника и загрузки](https://archive.ics.uci.edu/dataset/502/online+retail+ii).
Примеры и тесты проекта используют только синтетические значения; фактические
свойства реального файла необходимо устанавливать собственным аудитом.

| Exit code | Результат |
|---|---|
| `0` | Аудит завершён; возможны предупреждения |
| `2` | Аудит завершён с ошибками значений; все строки сохранены |
| `1` | Ошибка файла, структуры или записи; завершённого набора нет |
| `64` | Неверная команда или аргументы |

Все листы, в том числе скрытые и пустые, обрабатываются в порядке книги.
Первый непустой физический ряд каждого листа считается заголовком. Обязательны
`Invoice`/`InvoiceNo`, `StockCode`, `Description`, `Quantity`, `InvoiceDate`,
`Price`/`UnitPrice`, `Customer ID`/`CustomerID`, `Country`. Алиасы точные,
регистрозависимые; пробелы не удаляются. Два алиаса одного поля или отсутствие
обязательного поля на непустом листе — ошибка структуры. Дополнительные столбцы,
пустые ячейки заголовка и пустые листы допустимы.

Поддерживаются незашифрованные transitional OOXML `.xlsx` с обычными worksheet,
shared/inline strings и скалярными ячейками. XLS, XLSB, strict OOXML, chart sheets,
DTD и внешние XML entities не входят в профиль. Формулы не вычисляются, внешние
ссылки не загружаются. Форматирование и rich-text стили не воспроизводятся;
текстовые фрагменты объединяются с сохранением пробелов, индекс стиля сохраняется.
Исходная книга остаётся неизменной и нужна для полного восстановления оформления.

## Контракт артефактов загрузки

JSON/JSONL имеет `schema_version: 1`, UTF-8 без BOM и LF. Числовые значения ячеек
сохраняются **строками** из XML: `0.1000` не становится `0.1`, а текстовый ID
`00042` не становится числом. Порядок листов, строк, столбцов и диагностик фиксирован.

| Файл | Содержание |
|---|---|
| `raw_transactions.jsonl` | По записи на физический XML-ряд, включая заголовки и пустые ряды |
| `issues.jsonl` | Код, severity, источник, координаты, исходная ячейка, сообщение и связанная строка дубля |
| `audit.json` | Схемы/численности листов, проблемы, пропуски, число различных ключей и диапазон дат |
| `manifest.json` | Маркер завершения, версии, параметры, источник и hashes воспроизводимых артефактов |
| `run.json` | Время исполнения и версия JVM; не входит в воспроизводимые hashes |

Raw-запись содержит `source_sha256`, `sheet_index` (от 1), `sheet_name`,
`row_number` (от 1), `kind` (`header`, `data`, `empty`) и массив `cells`.
Номера отсутствующих рядов не материализуются: пропуски до последнего физического
ряда считаются в `absent_rows`. `physical_rows`, `header_rows`, `data_rows`,
`empty_rows`, видимость листа и соответствие полей столбцам записаны в manifest/audit.

Каждая ячейка содержит:

- `column`, `reference`: буква столбца и координата, например `F`, `F3`;
- `source_type`: OOXML `n`, `s`, `inlineStr`, `str`, `b`, `e`, `d`; при отсутствии `t`
  используется его стандартное значение `n`; у отсутствующей ячейки — `null`;
- `state`: `missing`, `blank`, `empty_string`, `value` или `formula`;
- `value`: текст или точная числовая строка; для формулы — `null`;
- `raw_value`: исходный текст XML `v`, в том числе индекс shared string или cache;
- `style`: исходный индекс стиля либо `null`;
- `formula`: текст формулы в `text` и исходные атрибуты (`t`, `si`, `ref` и другие),
  либо `null`; `cached_value`: разрешённое сохранённое значение формулы либо `null`.

Отсутствующие ячейки добавляются до ширины заголовка или текущей строки.
Отсутствующая ячейка, физически пустая ячейка и строка нулевой длины различимы.
Ведущие/конечные пробелы и Unicode-пробелы не очищаются. Rich text сохраняется как
объединённый текст без фонетических аннотаций. Строка с одними пустыми значениями
имеет `kind: empty` и сохраняется, но не считается транзакцией для проверок типов.

Неразбираемые или отсутствующие quantity/price/date — ошибки данных. Quantity
должно быть целым; price — конечным десятичным числом; числовые строки разрешены,
boolean/error ячейки недопустимы для этих полей. Неположительная цена, нулевое
количество, несогласованность префикса `c`/`C` со знаком количества, отсутствующие
ключи и возможные дубли — предупреждения. Отсутствующий customer ID не заменяется.
Каждая формула получает предупреждение; её cache не участвует в проверках типов,
знаков, ключей или диапазона дат. Формула в заголовке — ошибка структуры.

Даты проверяются как Excel serial с системой `1900`/`1904` из книги либо ISO local
`YYYY-MM-DD` / `YYYY-MM-DDTHH:mm:ss[.fraction]` без offset. Часовой пояс не назначается.
Serial 60 в системе 1900 (фиктивное 29 февраля) и отрицательные serial недопустимы;
serial 0 означает 1899-12-31 или 1904-01-01. Диапазон дат ограничен годом 9999.
Для сводного диапазона дробная часть serial переводится в наносекунды с HALF_UP;
исходная числовая строка не меняется. Денежные значения не округляются и не
преобразуются через `double`.

Возможный дубль сравнивается по каноническим полям и дополнительным столбцам,
типам, состояниям, исходным значениям и формулам, включая разные листы.
Координаты строки и индексы стилей не входят в сравнение; shared string сравнивается
по разрешённому тексту. Числа и строки не нормализуются. Для дополнительных
столбцов учитывается позиция. Повторные записи сохраняются, `related_row` указывает
на первое совпадение. SHA-256 fingerprints используются для сравнения; это
диагностика возможных дублей, а не правило удаления. `distinct_keys` также считает
различные представления ключа, без приведения числовых ID к текстовым.

Только `manifest.json` со `status: completed` и совпадающими SHA-256 из `artifacts`
обозначает готовый набор. `data_status` (`ok`, `warnings`, `errors`) отдельно описывает
качество данных. Manifest содержит basename и SHA-256 входа, версии CLI/профиля,
систему дат, параметры и их hash, листы и hashes raw/issues/audit. Пути и время
не входят в эти артефакты; manifest не хеширует себя. Одинаковые байты исходника,
basename и параметры дают одинаковые raw/issues/audit/manifest.

Каталог резервируется атомарно без перезаписи. Запись выполняется в `.partial`,
файлы закрываются и hashes проверяются, затем manifest публикуется последним
атомарным переименованием. Если файловая система не поддерживает это действие,
запуск завершается ошибкой. При сбое остаются `fatal.json` и частичные файлы;
диагностика также выводится в stderr. Если каталог недоступен, stderr остаётся
единственным каналом диагностики. Существующий output, включая пустой каталог,
никогда не используется повторно. После аварии запускайте в новый каталог.
Атомарность маркера не обещает сохранность при аппаратном сбое питания.

Чтение worksheet потоковое. Таблица shared strings, fingerprints дублей и
различных ключей занимают память пропорционально числу уникальных значений;
копия входного файла в `.partial` обеспечивает чтение и hash одних байтов.
При ошибке эта копия может остаться для диагностики. Результат не превращается
автоматически в `CleanEvent`: очистка, классификация и допуск в обучение — отдельный этап.

## Агрегация заказов

`aggregate_orders` принимает последовательность или генератор `CleanEvent`.
Каждая запись содержит строковые `event_id`, `invoice_id`, `stock_code`,
`customer_id` (строка или `None`), `event_time` (datetime без часового пояса),
`kind` (`sale` или `cancellation`), целое `quantity` и цену `unit_price` типа
`Decimal`. Количество положительно для продажи и отрицательно для отмены;
цена конечна и строго положительна. Неверные типы, знаки, `float`-цены и
timezone-aware даты отвергаются. Идентификаторы сохраняются без преобразований.

```python
from datetime import datetime
from decimal import Decimal

from repeatlab.aggregation import CleanEvent, aggregate_orders
from repeatlab.temporal import build_snapshot

events = (
    CleanEvent(
        "e1", "invoice-1", "A", datetime(2010, 12, 10), "sale", "product-1", 2, Decimal("1.25")
    ),
    CleanEvent(
        "e2", "invoice-1", "A", datetime(2010, 12, 10), "sale", "product-2", 1, Decimal("0.335")
    ),
)
result = aggregate_orders(events, service_codes={"DELIVERY"})
order = result.orders[0]
assert (order.line_count, order.quantity, order.stock_code_count) == (2, 3, 2)
assert order.total_amount == Decimal("2.835")

snapshots = build_snapshot(
    (order.to_temporal_order() for order in result.orders),
    snapshot_time=datetime(2011, 1, 1),
    observed_until=datetime(2011, 2, 1),
)
assert snapshots[0].history_order_count == 1
```

Один согласованный счёт даёт один `AggregatedOrder`: ключ счёта, покупатель,
время, вид события, число товарных строк, сумма единиц, число различных товарных
кодов и точная сумма `quantity × unit_price`. Округления нет, включая цены с
долями копейки; вычисление не зависит от precision, rounding и traps текущего
Decimal-контекста. Количество и сумма отмен остаются отрицательными. Отмены
сохраняются отдельными счетами и не вычитаются из предыдущих продаж.

Точный итог должен быть представим конечным значением `Decimal`. При выходе
за пределы представимости реализации `Decimal` агрегация вызывает `ValueError`
без округления и без возврата `NaN`. Настройки и флаги Decimal-контекста
вызывающего кода сохраняются, включая случай ошибки.

Результат содержит неизменяемые кортежи заказов и диагностики:

- `excluded_service_event_ids`: строки с кодами из явно переданного
  `service_codes` (по умолчанию пусто). Они не входят в число строк, единиц,
  товаров и сумму; служебный счёт без товаров не создаёт заказ.
- `possible_duplicate_event_ids`: группы ID строк с одинаковыми полями, кроме
  `event_id`, среди всех входных событий. Такие строки сохраняются. Повторение
  самого `event_id` вызывает `ValueError` для всего входа, даже если строка
  служебная или относится к конфликтному счёту.
- `quarantined_invoices`: счета с разными `customer_id`, `event_time` или `kind`.
  Каждая запись содержит `invoice_id`, имена конфликтующих полей и все исходные
  события. Проверка выполняется до фильтрации служебных кодов; строки карантина
  не дублируются в `excluded_service_event_ids`. Остальные счета обрабатываются.

Сочетание `None` и известного покупателя внутри счёта — конфликт. Если все ID
покупателя отсутствуют, заказ сохраняется с `customer_id=None`; адаптер
`to_temporal_order()` передаёт его без подстановки фиктивного клиента.
Заказы и карантин упорядочены по счёту, ID внутри диагностики — по строковому
порядку. Перестановка входных строк не меняет результат.

Агрегатор принимает классифицированные события и не загружает исходные файлы.
Для готового clean-набора используйте read_clean_dataset: проверка префикса счёта
выполняется при очистке и проверенном чтении. Коллизии номеров
счетов не исправляются составным ключом. Тест с синтетическим JOIN проверяет
отклонение размноженных `event_id` на входе агрегации; общего API для JOIN нет.
Агрегация выполняется в памяти, поэтому объём входа и размер точных десятичных
чисел ограничены доступными ресурсами.

## Временной контракт

`build_snapshot` принимает валидированные заказы, момент расчёта и явный конец
наблюдения. В историю входят покупки за предыдущие 180 дней, строго до момента
расчёта. Цель учитывает покупки в следующие 30 дней: левая граница включена,
правая исключена. Оба окна можно задать параметрами.

Покупатели без известного ID и без покупок в прошлом окне не включаются.
Отмена не считается покупкой. При неполном горизонте строка получает
`status="censored"` и `label=None`; её нельзя использовать как отрицательный исход.
Даты сохраняются в исходной временной шкале без назначения часового пояса.

Искусственные данные находятся в `data/fixtures/`, проверки — в `tests/`.
Большие исходные и обработанные данные не хранятся в Git.

## Очистка и проверенное чтение

```text
java -jar java/target/repeatlab-data.jar clean --input data/processed/run-001 --config configs/cleaning.json --output data/processed/clean-001
```

Команда проверяет завершённый ingest-набор, копирует входные артефакты в закрытый
рабочий каталог, сверяет hashes скопированных байтов и читает именно эту копию.
XLSX повторно не читается. Непригодные значения из завершённого raw-набора с
`data_status=errors` диагностируются построчно. Выходной каталог должен быть новым.

Политика `clean-v1`: sale требует положительных quantity/price и счёта без префикса
`c`/`C`; cancellation требует отрицательного quantity, положительной price и этого
префикса. Знаки и значения не исправляются. Непригодная строка изолирует весь
определимый счёт, включая его служебные позиции. Неопределимый invoice изолирует
только собственную строку. Разные customer/time/kind также изолируют весь счёт;
точные моменты сравниваются до сокращения точности. Дубли содержимого сохраняются.

Числовой ID должен быть точным целым: `42.0` и `4.2E1` становятся `"42"`.
Непустой текст сохраняется буквально, включая ведущие нули и пробелы. Отсутствующий,
пустой или состоящий только из Unicode White_Space customer становится `null`;
обязательные invoice/stock в таком случае непригодны. White_Space здесь означает
U+0009–000D, U+0020, U+0085, U+00A0, U+1680, U+2000–200A, U+2028–2029,
U+202F, U+205F, U+3000. Формулы в необходимых полях не имеют доверенного значения;
формулы только в description/country не блокируют событие.

Деньги передаются точной десятичной строкой, количество — JSON integer.
Время вычисляется напрямую из точного serial/ISO без `double` и округления аудита;
результат floor до микросекунды остаётся в прежнем дне на `23:59:59.9999996`.
Реальная потеря точности отмечается флагом. Поддерживаются годы 1–9999 без timezone,
системы Excel 1900/1904; фиктивный день serial60 исключён. Субмикросекундный порядок
теряется в clean, исходная точность остаётся доступна через происхождение в raw.

Конфигурация содержит ровно `policy_version: "clean-v1"` и массив строк
`service_codes`. Пустой массив допустим; никакой список кодов не угадывается.
Коды имеют буквальный смысл. Повторы устраняются, порядок канонизируется по Unicode
code point. Канонический JSON имеет отсортированные ключи, UTF-8 без BOM,
без незначащих пробелов и без ASCII-экранирования Unicode. Control escapes имеют
строчные hex-цифры, стандартные \b, \f, \n, \r, \t сохраняются; hash конфигурации — SHA-256
этих байтов без завершающего LF. Версия политики включена в hash. Неизвестные поля,
неверные типы и повторные JSON-ключи отклоняются.

Clean-артефакты используют `schema: "repeatlab-clean"`, `schema_version: 1`:

| Файл | Содержание |
|---|---|
| `clean_events.jsonl` | Восемь полей CleanEvent, provenance, quality_flags и is_service; включает принятые служебные строки |
| `dispositions.jsonl` | Ровно один outcome каждой raw data-строки: accepted_product, accepted_service или quarantined, причины и flags |
| `audit.json` | Полное покрытие, принятые/карантинные строки, отсутствующие customer, header/empty, counts причин |
| `manifest.json` | Завершение, версии, hashes входа и артефактов, каноническая конфигурация, counts и качество |
| `run.json` | Изменчивые сведения исполнения вне воспроизводимых hashes |

`is_service` согласован с конфигурацией; это флаг, отдельный от kind.
`provenance` содержит source_sha256, sheet_index, sheet_name, row_number.
`event_id` равен SHA-256 UTF-8 строки `source_sha256:sheet_index:row_number` с обычными
десятичными координатами. Он не зависит от классификации, содержимого или конфигурации.
Порядок записей — исходный порядок листов/строк; ключи JSON и массивы flags/reasons
сортируются. Собственная ошибка строки отличается от `INVOICE_INVALID`, применяемой
ко всем строкам неполного счёта, и `INVOICE_CONFLICT_*` для конфликта полей.

Exit0 означает completed без карантина (предупреждения допустимы); exit2 — completed
с карантином и пригодным подмножеством. Exit1 — ошибка набора/структуры/записи, exit64 —
неверный запуск. Manifest публикуется последним атомарно. При ошибке завершённого
manifest нет, по возможности сохраняется fatal.json. Никакой output не перезаписывается.

Reader проверяет весь набор до выдачи событий: версии, hashes, конфигурацию,
происхождение, уникальность, dispositions, counts и согласованность счетов.
Один файл событий без manifest не является проверенным набором. Возвращаются
неизменяемые события/коды/метаданные; цена — Decimal, время — naive datetime.
`dataset.aggregate()` передаёт согласованные service_codes в существующий агрегатор,
чтобы служебные строки не попали в суммы по умолчанию. Дальнейший snapshot использует
прежний явный observed_until и неизменённые временные границы.

Java хранит в памяти состояние счетов и происхождения, а ячейки обрабатывает потоково.
Python проверяет и возвращает весь принятый набор в памяти. SHA-256 проверяет целостность,
но не является подписью автора: источник набора должен быть доверенным. Объединение
нескольких raw-наборов и автоматическое исправление коллизий invoice не поддерживаются.
