# Разработка

Перед изменением поведения согласуйте цель задачи и критерии приёмки.
Сохраняйте изменения небольшими и добавляйте проверки затронутых контрактов.

## Проверки

```text
sh ./mvnw -B -f java/pom.xml verify
uv python install
uv sync --locked --dev
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy src tests
uv run --locked pytest
uv build --no-sources
```

На Windows можно выполнить `./scripts/check.ps1`: он останавливается при первой ошибке.
Зависимости воспроизводятся из `uv.lock`; обновления зависимостей рассматриваются
вместе с изменением lock-файла. Обычная проверка не должна обновлять версии.

Java-часть требует Temurin 25.0.5+8. Maven 3.10.0 закреплён Wrapper с SHA-256;
на Windows используйте `./mvnw.cmd`. Библиотеки POI 6.0.0, Jackson 2.21.8 LTS,
JUnit 6.1.3 и build plugins закреплены в `java/pom.xml`; транзитивные версии
задаются опубликованными POM этих релизов. Изменения зависимостей проверяйте вместе
с Java и Python тестами. Java компилируется с `-Xlint` и `-Werror`.

Сначала соберите JAR, затем запускайте pytest: межъязыковые тесты запускают именно
`java/target/repeatlab-data.jar` и не пропускаются при отсутствии Java или JAR.
Тестовые XLSX создаются из синтетического OOXML с буквальными числовыми строками;
не заменяйте их fixture, полученными из реальных данных или через `double`.
Проверки охватывают сохранение значений, проблемы строк, завершение/ошибки записи,
SHA-256 и повторяемость. `scripts/check.ps1` выполняет оба набора проверок,
останавливается при первой ошибке и использует `JAVA_HOME`, если он задан.

## Pull requests

Создавайте отдельную ветку для каждой задачи. В PR опишите изменившееся поведение,
способ проверки и ограничения. Изменения тестов и контрактов должны быть обоснованы.
Не включайте данные, локальные настройки, окружения и результаты сборки.
Перед коммитом просмотрите список файлов и полный staged diff.

Clean-тесты проходят весь путь ingest → clean → Python → orders → snapshot.
Изменения проверяемого обмена должны сохранять strict JSON, hashes, provenance,
полное покрытие dispositions и согласованные service_codes. Используйте буквальные
точные значения, включая субмикросекундные границы и Unicode ID. Не подменяйте
точную проверку счёта сравнением уже усечённого времени.
